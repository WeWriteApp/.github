# WeWriteApp/.github agent guide

This repository holds the WeWrite organization's community health files. It has no app code.

## What lives here

- `README.md` — short readme for the organization.
- `profile/README.md` — the profile readme shown on the [WeWriteApp organization page](https://github.com/WeWriteApp). It describes WeWrite, links the website, docs, social accounts, and supporter pages.
- Organization-wide defaults, when added, such as issue and pull request templates.

There is no build, no test suite, and no deploy. Changes here are edits to Markdown files only.

## How to work in this repo

- Read the file you are about to change first. Do not rewrite a file from memory.
- Keep edits small and focused on one change. Do not rename, move, or rewrite files that are not part of the requested change.
- Keep links working. Check that any link you add or change points at a real page. Never guess a URL.
- Use plain language and short sentences.
- Match the tone of the existing profile readme: welcoming, plain, and about what WeWrite is.

## Verification rules

- Verify against live state, never guess. If a link, handle, or fact cannot be checked, say so instead of writing it in.
- After an edit, read the changed file back and confirm only the intended lines changed.
- Do not claim a change is live on github.com until it is merged to `main`.

## What never to do

- Never put a secret, token, password, or private key in any file in this repo.
- Never force-push. Never push directly to `main`.
- Never guess a preview URL. There is no preview for this repo.
- Never invent a build, test, or deploy command. This repo has none.
- Never edit the profile readme to promise a feature, date, or price that has not been confirmed.
